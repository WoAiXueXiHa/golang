## 1. 类型

> 类型决定一个值可以取什么范围，以及这个值支持哪些操作

Go 是静态类型语言，表达式的类型通常在编译阶段确定

**Go 类型有三个关键概念：**

- Defined type：定义类型，根据类型定义创建、具有独立身份的类型
    
- Underlying type：类型定义最终依据的底层结构
    
- Type alias：为已有类型引入另一个名称，不创建新类型
    

 type UserID int64  
 type OrderID int64  
 type MyInt = int64

`UserID` 和 `orderID` 是一个新定义的类型，`MyInt` 是 `int64` 的别名

虽然 `UserID` 和 `OrderID` 的底层类型都是 `int64`，但它们是两个不同的类型：

![image-20261114163749764](https://gitee.com/binary-whispers/pic/raw/master///20261114163752031.png)

为什么这么设计？**底层数据表示相同不代表业务含义相同**，比如一个用户 ID 和一个订单 ID 都可以使用 `int64` 存储，但在业务代码中不应该随意混用

类型别名和定义类型有什么区别？

 type A int  
 type B = int  
 ​  
 var x int = 10  
 var a A = A(x)  
 var b B = x

`A` 是新的定义类型，所以 `int` 变量 `x` 不能直接赋值给 `A` 变量，需要显式转换

`B` 是 `int` 的别名，所以 `B` 与 `int` 是同一个类型

看一段代码加深理解：

 package main  
 ​  
 type UserID int64  
 type OrderID int64  
 type Alias = int64  
 ​  
 func main() {  
     var a UserID = 100  
     var b OrderID = 200  
     var c int64 = 300  
     var d Alias = 400  
 ​  
     a = UserID(b) // 合法，底层都是 int64，定义类型不同但显式转化了  
     a = c         // 非法，虽然底层都是 int64，但是定义类型不同  
     c = d         // 合法，类型别名不会创建新类型  
     a = 500       // 合法，500 是一个无类型整数常量，可以根据上下文确定类型  
 }  
   

注意：在 Go 里，还没定死类型的字面量或常量就像“通用原材料”**——虽然变量之间严禁互相跨类型赋值，但只要目标变量**装得下这个常量的值（不溢出、不丢精度），就可以直接塞给它，省去手动写类型转换的麻烦

 type Small int8  
 ​  
 var x Small = 127 // 合法  
 // var y Small = 128 // 编译错误

因为 `int8` 的范围是 -128～127，存在溢出风险

## 2. 变量

> 变量是用于保存值的存储位置，它具有确定的类型，并且在程序执行过程中可以被赋予新值

```
var x int = 10
x = 20
```

变量 `x` 的类型始终是 `int`，变化的是它存储的值

可以理解成变量是一个有特定颜色（类型）的箱子，而值会扔进这个变量来存储

Go 有四种常见的变量声明方式：

```go
// 显式类型，显式初始化
var a int = 10

// 显式类型，不初始化
var b int

// 省略类型，由初始化表达式推导
var c = 10

// 短变量声明，只能在函数中使用
d := 10
```

同时，Go 有一个重要的设计：**声明变量时，即使没有显式初始化，它也会被初始化为该类型的零值**

以下是不同类型变量的零值：

|类型|零值|
|---|---|
|`int`、`float64` 等数值类型|`0`|
|`bool`|`false`|
|`string`|`""`|
|指针|`nil`|
|Slice|`nil`|
|Map|`nil`|
|Channel|`nil`|
|Interface|`nil`|
|Function|`nil`|
|Array|每个元素的零值|
|Struct|每个字段的零值|

```go
type User struct {
    ID     int
    Name   string
    Active bool
}

func main() {
    var u User
    fmt.Printf("%+v\n", u)
}
```

输出：`{ID:0 Name: Active:false}`，`User` 结构体的每个字段都被初始化为对应类型的零值

注意：**零值不等于可以直接使用**

对于 slice 的零值：

```go
var s []int

fmt.Println(s == nil) // true

s = append(s, 1)
fmt.Println(s) // [1]
```

nil slice 可以直接使用 `append`

对于 map 的零值：

```go
var m map[string]int

fmt.Println(m == nil) // true
fmt.Println(m["a"])   // 0

// m["a"] = 10 // panic!

m = make(map[string]int)
m["a"] = 10
```

nil map 可以读，但是不能写入新键值，因为目前没有底层的数据结构，所以需要先初始化构造出底层的结构

对于 channel 的零值：

```go
var ch chan int

ch <- 10 // 永久阻塞，除非所在 goroutine 被其他机制终止
```

nil channel 的发送和接收操作都会永久阻塞

还有一个有意思的点：短变量声明允许在特定条件下重新声明已有的变量

```go
func main() {
    x := 10

    x, y := 20, 30

    fmt.Println(x, y) // 20 30
}
```

在同一个作用域内，`x` 已经存在，但是 `y` 是新变量

Go 允许这种重新声明，要求：
- 至少有一个非空白标识符是新变量
- 被重新声明的已有变量类型不变
- 已有变量必须在同一个作用域中声明
- 左侧名称不能重复

最后用一段代码做个总结：

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	fmt.Println("=== 1. nil 切片 vs 空切片 ===")
	var s1 []int     // nil 切片（零值）
	s2 := []int{}    // 空切片（已初始化，长度0）

	fmt.Printf("s1 (var s []int): len=%d, cap=%d, s1==nil: %v, 底层指针: %p\n",
		len(s1), cap(s1), s1 == nil, unsafe.SliceData(s1))
	fmt.Printf("s2 (s := []int{}): len=%d, cap=%d, s2==nil: %v, 底层指针: %p\n",
		len(s2), cap(s2), s2 == nil, unsafe.SliceData(s2))

	fmt.Println("\n=== 2. new(map[string]int) 的陷阱 ===")
	mPtr := new(map[string]int) // 为 map 变量本身分配内存，返回 *map[string]int

	fmt.Printf("mPtr 本身 (指针地址): %p, mPtr == nil: %v\n", mPtr, mPtr == nil)
	fmt.Printf("*mPtr 解引用后的值: %v, *mPtr == nil: %v\n", *mPtr, *mPtr == nil)

	// 如果此时直接执行 (*mPtr)["a"] = 1，会直接触发 panic: assignment to entry in nil map
	// 必须先用 make 初始化底层哈希表：
	*mPtr = make(map[string]int)
	(*mPtr)["a"] = 1
	fmt.Printf("make 初始化后写入成功: %v\n", *mPtr)

	fmt.Println("\n=== 3. if 作用域内的 := 变量遮蔽 (Shadowing) ===")
	x := 10
	fmt.Printf("外层初始: 值=%d, 内存地址=%p\n", x, &x)

	if true {
		// 使用 := 会创建一个全新的局部变量 x，遮蔽（Shadow）外层的 x
		x := 20
		fmt.Printf("if 内部:  值=%d, 内存地址=%p  <-- 地址变了！说明是新变量\n", x, &x)
	}

	fmt.Printf("if 结束后: 值=%d, 内存地址=%p  <-- 外层变量完全没受影响\n", x, &x)
}
```

> **new 和 make 有什么区别？**
> new 用于任意变量的初始化操作，返回对应变量类型的零值指针，不会初始化底层的数据结构；make 专用于有底层数据结构变量的初始化，会初始化对应变量底层数据结构，返回具体的类型


## 3. 常量

> Go 的常量可以没有具体类型，并且无类型常量具有比普通变量更灵活的赋值和运算规则

先看代码：

```go
const a = 10
const b int64 = 10

var x int = a
var y int = b
```

后两个赋值能否成功？第一条合法，第二条非法，原因是：`a` 是无类型的整数常量，并没有被绑定为 `int` 或者 `int64`，所以可以根据目标类型确定最终使用的类型，`b` 已经明确是 `int64` 了，就不能直接给 `int` 变量赋值

但是你可能会疑惑：

```go
const a = 10
x := a

fmt.Printf("%T\n", x)
```

这段代码明明输出 `int` 啊，`a` 明明是无类型的的整数常量，这里有个**默认类型**的概念，当无类型常量出现在需要确定具体类型、但没有其它目标类型约束的上下文中时，会使用它的默认类型

## 4. 类型转换

先区分类型转换和赋值的区别：

- 类型转换：把源表达式转成目标类型
- 赋值：把源表达式装进目标类型变量的箱子

对于类型转换，就涉及到了截断、溢出和精度丢失三个问题

### 4.1 浮点数转为整数

```go
func main() {
    var x float64 = 3.9
    var y int = int(x)
  
    var a float64 = -3.9
    var b int = int(a)

    fmt.Println(y, b) // 3 -3
}
```

浮点数转成整数，舍弃小数部分，**向零截断**，不是四舍五入

### 4.2 大整数转成小整数

```go
var aa int16 = 258
bb := int8(aa)

fmt.Println(bb) // 2
```

`int8` 只有 8 位，而 258 的二进制表示是：

```text
258 = 00000001 00000010
                   ↑
                低 8 位
```

转换为 `int8` 时，保留低 8 位，转成十进制就是 2

再看一个例子：

```go
var xx int16 = 255
yy := int8(xx)

fmt.Println(yy) // -1
```

保留低 8 位是：`1111 1111`，按照有符号解释就是 -1

### 4.3 整数转浮点数

```go
var xxx int64 = 9007199254740993
yyy := float64(xxx)

	fmt.Printf("%.0f\n", yyy) // 9007199254740992
```

因为 `float64` 有效进度只有 53 个二进制位，不能精确表示一个大整数，所以最后会有精度损失

## 5. 赋值兼容性

> 赋值兼容性解决的问题是：一个类型为 V 的值，能否不经过显式转换，直接赋值给类型为 T 的变量

### 5.1 类型完全相同

最简单的情况：

```
var a int = 10
var b int

b = a // 合法
```

`a` 和 `b` 都是 `int`，所以可以直接赋值

### 5.2 底层类型相同，并且至少一方不是定义类型

```go
type UserID int64
type OrderID int64
type Alias = int64
```

先理清楚关系：

|类型|是否为定义类型|底层类型|
|---|---|---|
|`UserID`|是|`int64`|
|`OrderID`|是|`int64`|
|`Alias`|是，作为 `int64` 的别名|`int64`|
|`int64`|是，预声明定义类型|`int64`|

```go
var a UserID = 10
var b OrderID = 20
var c int64 = 30

// a = b // 非法
// a = c // 非法
```

虽然它们的底层类型相同，但 `UserID`、`OrderID` 和 `int64` 都是定义类型

### 5.3 interface 的赋值

先不研究 interface 的底层实现，只研究赋值规则

#### 实现了接口就能赋值

```go
type Sender interface {
    Send() error
}

type EmailSender struct{}

func (e EmailSender) Send() error {
    return nil
}

func main() {
    var s Sender
    s = EmailSender{} // 合法
    _ = s
}
```

`EmailSender` 的方法集包含接口要求的 `Send() error` 方法

#### 值接收和指针接收

```go
type Sender interface {
    Send()
}

type EmailSender struct{}

func (e *EmailSender) Send() {}

func main() {
    var s Sender

    // s = EmailSender{}  // 编译错误
    s = &EmailSender{}    // 合法

    _ = s
}
```

- `EmailSender` 的方法集不包含指针接收者方法 `Send`
- `*EmailSender` 的方法集包含该方法
所以只有 `*Emailsender` 满足这个接口。这里还有个容易混淆的地方：

```go
e := EmailSender{}
e.Send() // 合法
```
这里可以直接调用，`e` 是可寻址变量，编译器可以将调用理解成为 `(&e).Send()`，这可以理解成一种语法糖

#### interface 的 nil 陷阱

```go
type MyError struct{}

func (*MyError) Error() string {
    return "error"
}

func getError() error {
    var e *MyError = nil
    return e
}

func main() {
    err := getError()
    fmt.Println(err == nil)
}
```

输出的是 `false`，interface 值包含动态类型和动态值，要保证两者都为 `nil`，整个 interface 才是 `nil`

## 6. 总结

Go 是静态类型语言，**Defined Type 具有独立的类型身份，Type Alias 不创建新类型**，底层类型相同不代表可以直接赋值

变量始终具有确定的类型，未显式初始化时使用零值；`var` 和 `:=` 只是不同的声明方式，`new` 返回零值指针，`make` 用于初始化 Slice、Map 和 Channel

**无类型常量可以根据上下文适配目标类型，但必须满足可表示性要求**；没有目标类型约束且需要具体类型时，才使用默认类型

**类型转换和赋值是两套规则**：显式数值转换可能发生截断、溢出或精度损失，而直接赋值必须满足 Assignability 规则
